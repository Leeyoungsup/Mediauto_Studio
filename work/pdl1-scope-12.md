# 12번 PD-L1 CPS·TPS 동시 표시 범위

## 적용 결정

현재 개발 서버에서 활성화된 동시 표시 조합은 없다. 예제의 CPS는 보관 결과로 열람할 수 있다. 03번 명령과 기준 코드의 출력 계약은 확인했다. 작업공간에서 03번의 승인 기록, 같은 검체의 독립 판독 정답, 암종·염색별 두 모델의 검증 보고서는 확인되지 않았다.

| 조직과 결과 | 기준 코드에서 확인된 입력 프로필 | 저장 출력 | IMS 동작 |
| --- | --- | --- | --- |
| 위선암 범위 검토 | `Stomach` · `PDL1_ST_CPS_detection.pt` · `pdl1_flat_5class` | CPS, 클래스별 집계, level-0 세포 중심점 | 기술적으로 일치하는 원본 CPS 한 건을 열람할 수 있다. 검체와 염색 근거가 없으면 보관 점수로 표시한다. |
| 비소세포폐암 범위 검토 | `Lung` · `PDL1_TPS_detection.pt` · 3개 클래스 | TPS %, 클래스별 집계, level-0 세포 중심점 | 기술적으로 일치하는 원본 TPS를 같은 방식으로 열람할 수 있다. 예제 TPS 원천에는 실행 모델 기록이 없어 기존 서버에 추가하지 않았다. |
| 동일 검체에서 CPS와 TPS | 같은 WSI·검체·조직형, PD-L1 염색 클론·장비·프로토콜, 동일 분석 영역 | 각 모델의 검증된 원본, 체크포인트 SHA-256, 분석 버전, 독립 검증 근거 | 연결한 두 원본에 대해 구체적 검증 기록이 모두 일치할 때 두 점수를 표시한다. 오버레이는 선택한 원본 기준이다. |
| 다른 검체, 프로토콜 또는 염색, 서로 다른 주석 영역, 사용자 수정본 | 불일치하거나 근거가 불충분한 결과 | 원본 점수와 수정 세포가 섞일 가능성이 있는 저장 결과 포함 | 동시 표시를 차단한다. 모호하거나 맞지 않는 개별 점수도 화면 및 결과 API에서 숨긴다. |

위 표는 IMS에 연결한 두 모델의 계약이다. FDA 22C3 문서는 NSCLC에서 TPS, 위 또는 위식도접합부 선암 등에서는 CPS를 다룬다. 이 문서는 FDA 문서에 기술된 검사법의 참고 자료로 사용했다. IMS 모델, 다른 클론이나 염색 플랫폼, 조직형 확대에 대한 검증 자료는 별도로 필요하다. [FDA PD-L1 IHC 22C3 pharmDx 검사 문서](https://www.accessdata.fda.gov/cdrh_docs/pdf15/P150013S032D.pdf)

Techcyte 참조 PDF 42쪽의 화면에서는 두 점수가 동시에 보인다. 발표자는 적용 범위가 암종과 알고리즘에 따라 달라질 수 있다고 설명했다. 이 화면은 배치 참고로 사용했다. 폐 조직이라는 설명이나 화면 수치는 IMS 검증 자료로 채택하지 않았다.

## 검토한 점수 규칙

기준 커밋 `d3741bc`의 `backend/app/ai_pipelines/scoring.py`를 따른다.

- CPS는 `(종양 양성 + 면역 양성) / (종양 음성 + 종양 양성) × 100`으로 저장 집계를 대조한다. 이 모델은 클래스 0·2·3을 사용하며 상한은 100이다.
- TPS는 `종양 양성 / (종양 음성 + 종양 양성) × 100`으로 저장 집계를 대조한다. 이 모델은 클래스 0·1을 사용한다. 비종양 클래스는 집계에서 제외한다.
- 검증에는 저장 정밀도인 소수 둘째 자리까지 사용한다. 종양 분모 0, 필수 클래스 집계 누락, 잘못된 클래스 또는 저장값과 집계 불일치는 점수 확인 불가로 처리한다. 분모가 양수인 실제 0은 그대로 표시한다.
- 두 모델에서 자동 변환하거나 한 모델의 클래스 집계로 다른 모델 점수를 생성하는 경로는 없다. 비교 시에는 스캔별 권한을 동일하게 적용한다. 점수 검산은 산술 일관성 검사다.

## 검증 자료 연결 계약

검증 자료는 운영자가 기관 검토 후 서버 전용 카탈로그에 관리한다. 브라우저나 공개 API에서 검증 기록을 생성할 수 없다. 합성 기록은 격리 테스트에만 사용했다.

1. 각 원본을 `import_pdl1 --validation-context`로 가져올 때 결과 파일 SHA-256인 `source_digest`, `checkpoint_sha256`, `score_schema`, 그리고 `input`을 전달한다. `input`은 비식별 `specimen_ref`, `histology`, `stain`(PD-L1), `clone`, `platform`, `protocol`, `region_ref`로 구성한다. 스키마 표기는 CPS `pdl1_flat_5class`, TPS는 클래스 0–2 계약을 뜻하는 `tps_3class`다.
2. 검증을 마친 경우 같은 기관·WSI 카탈로그의 `comparison-validation.json`에 정확한 `cps_snapshot_id`, `tps_snapshot_id`, 동일한 `context`, `reviewed_by`, 공동 기록의 `reference`, 각 모델의 `cps_reference`, `tps_reference`를 연결한다. 참조는 비식별 기관 검증 문서 ID를 사용한다.
3. 모델별 독립 검증에는 명시한 입력 조건·해당 체크포인트·분석 버전에 대한 기준 판독, 세포 집계·점수 기대값, 검체 적합성과 실패 처리, 공동 표시를 허용하는 검토 결론이 필요하다. 파일 형식만으로 문서의 임상적 타당성을 심사할 수 없다.
4. 원복하거나 검증 효력을 거두면 해당 검증 기록을 카탈로그에서 비활성화한다. 다음 조회에 동시 표시가 바로 차단된다. 기존 파일과 감사 이력에는 DB 마이그레이션을 적용하지 않는다.

## 검증 및 재현

`backend/tests/test_pdl1_policy.py`에서 기준 집계, 0, 상한, 병렬 표시 승인 조건, 검체·조직형·염색·영역·체크포인트·스냅샷 불일치를 검증한다. `scripts/verify-integration.sh`에서 기존 PostgreSQL 권한과 Chrome 워크플로를 함께 실행한다.

베이스의 예제 NDPI·SVS에서 CPS·TPS 저장 집계 4건을 읽어 산술 일치 여부를 확인했다. Chrome의 별도 합성 시나리오에서는 두 결과가 같은 WSI에 있어도 근거가 없을 때 수치 비노출, 합성 근거가 정확히 일치할 때 두 카드 표시, 클론 불일치 시 다시 비노출되는 흐름을 확인했다. 실제 임상 검증 자료가 있는 동시 표시 사례는 확인되지 않았다.
