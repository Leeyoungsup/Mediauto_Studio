## 사용자 흐름

1. **Case Details → Requests → New Request**에서 **AI Analysis**를 선택하고 **Target Scan**, **Execution Model**, **Request Details**를 입력한다. 모델 실행 없이 기존 스냅샷을 수동으로 연결하는 경로도 같은 화면에서 선택할 수 있다.
2. **Model Runs**에서 Queued, Running, Completed, Failed, Cancelled와 모델 레시피 버전을 확인한다. 케이스 관리자 또는 요청을 만든 현재 배정 병리의가 취소·재실행을 수행한다. 취소는 작업 상태를 즉시 종결하고 실행 중인 로컬 어댑터에 취소를 전달한다. 네이티브 읽기가 끝난 뒤에 반환되는 결과는 취소본에 기록되지 않는다. 재실행은 새 시도를 만들며 이전 시도와 결과는 보존한다. 보관 결과의 재실행에서는 처음 고정한 스냅샷을 사용한다.
3. 자문은 같은 **Requests**에서 요청할 병리의를 지정한다. 담당 병리의가 작업을 시작하고 요청 범위의 스캔을 열어 답변과 완료 상태를 기록한다. 요청 변경은 기존 수신자·알림 설정에 따라 전달된다.
4. 관리자는 **Settings → Analysis Pre-run Rules**에서 모델과 정규화된 염색명을 고르고 규칙을 켠다. 기본값은 규칙 없음이다. 작업자는 검토 시작 전인 해당 기관 케이스의 등록된 **QC Passed** 스캔마다 모델별 한 건을 자동 등록한다. 수동 요청으로 이미 해당 스캔·모델 작업이 있으면 사전 규칙은 중복 작업을 만들지 않는다. 규칙 비활성화는 이후 자동 등록에 적용한다.
5. 배정 병리의가 **IHC Review and Best Block**에서 IHC 스캔, 수기 판정, 같은 검체의 best block과 검토 사유를 기록한다. 해당 스캔의 완료 작업을 선택할 수 있다. 블록은 **Case Editor**에 먼저 등록한다. 같은 검체·마커의 정정은 새 버전이다.
6. **Report Draft → Result Evidence**에서 작업의 특정 시도와 IHC 판정 버전을 참조한다. 보고 버전에는 선택한 근거를 복사해 보존한다. 보관 원본 결과는 링크에서 기존 WSI 오버레이를 열 수 있다. 기존 승인된 Mock LIS 송신에는 본문 섹션이 포함되므로 송신할 판정 값은 작성·승인한 본문에 반영한다.

## 상태·DB·운영

- 요청 생성과 첫 작업 생성은 한 트랜잭션에서 처리한다. 같은 생성 키와 같은 입력은 재사용한다. 재실행 키는 원래 시도와 함께 검증한다. 작업은 이전 원본의 파일 지문, 모델 레시피 버전과 염색을 확인한다. 상태·실패 사유와 변경자는 Case Logs에 남긴다.
- 워커는 PostgreSQL 잠금으로 작업을 선점한다. 중단되어 30초가 지난 실행은 실패로 복구되며 동일 입력으로 새 시도를 만들 수 있다. 실행은 로컬에서 처리하고 외부로 WSI를 전송하지 않는다.
- `0019_analysis_execution`은 `analysis_rules`, `analysis_runs`, `ihc_reviews`를 추가한다. 기존 요청 및 보고 데이터는 변환 없이 유지한다. 신규 규칙·작업·검토가 있는 DB의 다운그레이드를 차단한다. 되돌릴 경우 서비스를 정지하고 현재 상태를 백업한 뒤 이전 코드와 배포 전 백업을 격리 DB에서 먼저 확인한다.
- PostgreSQL 18.6에서 `0018 → 0019 → 0018 → 0019`를 검증했다. 기존 케이스·요청·보고·주석 스키마 보존, `alembic check` 및 신규 규칙 데이터가 있는 경우의 롤백 차단을 확인했다.

## 검증

- Python 3.10.20, PostgreSQL 18.6, Node 22.12.0, Chrome 146을 사용했다. API 시나리오는 취소 신호, 실패와 재실행, 중복 키, QC 통과 조건, 염색·권한·스캔·블록 제약, 보고 버전과 감사를 확인한다.
- 통합 Chrome 시나리오는 합성 CPS 보관 원본과 실제 예제 SVS에서 원본 재생·고정된 재실행, QC 사전 실행, 수기 판정·best block 및 보고 근거 저장을 검증한다. 격리 Chrome 실행에서는 예제 NDPI 사전 검사도 검증했다. `MEDIAUTO_DEMO_PORT=19941 scripts/verify-integration.sh`에서 백엔드 테스트 37개, Chrome 시나리오 18개를 통과했다. 처음 사용한 시연 케이스의 검토 완료 잠금은 기존 동작이다. 새 시나리오는 별도 검토 전 케이스를 사용한다.
- `./start.sh` 실행 전 개발 DB를 `.runtime/before-analysis-0019-20261124T193245.dump`에 백업했다. 9920에서 마이그레이션 적용, 기존 데이터 건수 유지 및 관리자의 실행 옵션 조회와 비활성 기본값을 확인했다.
- 기관 검증과 AGENTS 명령표 사용자 확인은 대기 중이다.
