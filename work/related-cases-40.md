# 40. 연관 Pap·조직생검 케이스 대조와 독립 WSI 비교

## 참조와 범위

- PDF 47쪽에는 Pap 화면과 연관 조직생검 뷰어가 각각 열린 장면이 보인다. 발표자는 이전 Pap 또는 생검 케이스의 독립 비교와 연관 케이스 배너를 설명했다. 기관 간 환자 매칭 기준·권한이나 임상 비교 검증 자료는 제시되지 않았다. [참조 PDF](../reference/Techcyte_IMS_Demo_Screen_Analysis.pdf)
- 등록된 내부 환자 ID, 검체·슬라이드·스캔 연결, 기존 Case RBAC·QC와 WSI 타일 렌더러, Case Logs를 재사용했다. 외부 시스템에 쓰거나 환자·검체를 자동 병합하는 작업은 없다.

## 대조와 승인

1. 등록된 케이스의 **Case Details** 또는 **WSI Viewer → Related Pap and Biopsy Cases**를 연다. 확인한 내부 환자 레코드가 필요하다. 같은 내부 환자 ID에 연결됐고 현재 계정이 두 케이스 모두를 열 수 있을 때만 후보가 검색된다. 독립 입력된 동명이인, 서로 다른 내부 ID 또는 환자 누락은 연결할 수 없다.
2. **Source Scan**과 **Related Scan**에서 각 검체·스캔을 선택한다. 한쪽은 QC 허용 Papanicolaou 스캔, 다른 쪽은 QC 허용 H&E 스캔이 필요하다. **Review Source Case**와 **Review Related Case**로 두 원천 케이스를 확인할 수 있다. 승인자가 환자 일치와 선택한 H&E 검체의 조직생검 여부를 각각 확인하고 사유를 적는다.
3. **Confirm Related Link**를 누르면 잠금된 현재 케이스·환자·검체·슬라이드·스캔을 다시 확인한다. 조회 이후 연관 레코드 버전이 바뀌거나 등록 파일과 현재 파일이 다르면 다시 대조하도록 안내한다. 관리자는 기관 내 두 케이스에 접근할 수 있어야 하며, 병리의는 두 케이스 모두 기존 배정에 따른 접근 권한이 필요하다.
4. **Related Link History**에서 승인자·시각·사유, 확인 또는 해제 상태를 확인한다. **Unlink → Confirm Unlink**는 사유와 함께 새 감사 이력을 남긴다. 양쪽 **Case Logs**에서 `related_case_link` 대상으로 조회할 수 있으며, 연결 감사는 양쪽에 대한 접근 권한이 있는 경우에 표시한다.

## 독립 WSI 비교

- **Open Independent Comparison**은 현재 원래 뷰어 탭을 유지하면서 별도 탭을 연다. **Primary Case**와 **Related Case**에 각 Case ID와 검체를 표시한다. 관련 케이스에서 열었다면 그 케이스가 Primary가 된다. 승인한 두 스캔의 WSI는 읽기 전용이며 각 패널에서 줌·팬·미니맵을 따로 조작한다. 다른 검체·스캔을 비교할 때는 새로 대조한다.
- 비교의 데이터, 메타데이터, overview와 타일 요청마다 현재 두 케이스의 접근 권한, 환자 식별자, 검체·스캔 및 QC, 연결 상태를 검사한다. 접근 권한 회수, 링크 해제 또는 환자 재연결로 불일치가 생기면 다음 요청부터 비교 파일을 차단한다. 열린 비교 화면은 약 2.5초 간격 및 탭이 다시 보일 때 재검증하며 거부되면 두 뷰어를 비운다. 원래 케이스를 독립적으로 열 수 있는 권한은 기존 규칙을 따른다.

## 데이터와 복구

- `0026_related_case_links`는 `related_case_links`를 추가한다. 승인 당시 환자 내부 ID와 두 케이스·검체·스캔을 저장한다. 동일 승인 요청의 재시도 및 동시 중복 링크를 제약으로 처리한다.
- 승인과 해제는 링크 상태와 감사 이벤트를 같은 트랜잭션에 기록한다. 감사에는 행위·사유·대상 링크와 시각이 남는다. 링크 해제는 원래 환자·검체·슬라이드 및 검토 상태에 영향을 주지 않는다.
- 빈 연결 테이블이면 `alembic downgrade 0025_pap_review`로 돌아갈 수 있다. 승인 또는 해제 이력이 있으면 다운그레이드를 차단한다. 백업을 보존한 후 버전과 이력을 함께 복구한다.

## 검증 결과

- Python 3.10.20, PostgreSQL 18.6, Node 22.12.0, Chrome 146.0에서 수행했다. 실제 SVS·NDPI를 배경으로 사용했고 환자·케이스·검체와 링크 승인은 합성했다. 기재된 실제 기관 환자 연결은 여전히 대기 상태다.
- 격리 Chrome에서 다른 내부 환자 ID의 동명이인, 환자 미연결, 검체 불일치, 승인 확인 누락, 반대쪽 접근 권한 누락을 확인했다. 승인 재시도와 중복 연결, 재배정 이후의 차단, 환자 연결 변경과 링크 해제 이후의 메타데이터·타일 차단을 검증했다.
- 새 탭의 두 케이스 표시와 원래 뷰어 유지, NDPI·SVS 각각 열기와 한쪽 팬·줌 시 반대쪽 중심·배율 유지, 권한 회수 후 비교 화면 정리와 양쪽 Case Logs의 승인·해제 이벤트를 확인했다. 비교 도구는 WSI 툴바의 아이콘으로 배치했다. 2560px·390px 레이아웃을 다시 검증했다.
- 격리 DB `0025 → 0026 → 0025 → 0026`, `alembic check` 및 링크가 있는 경우의 다운그레이드 보호를 확인했다. 개발 DB를 `.runtime/before-related-cases-0026-20261124T213841.dump`에 백업한 뒤 9920에 적용했다. 기존 데이터·설정 건수, 배포 화면, 인증과 EMR 미설정을 확인했다.
- 전체 `MEDIAUTO_DEMO_PORT=19945 scripts/verify-integration.sh`에서 TypeScript/Vite 빌드, 백엔드 테스트 58개와 Chrome 시나리오 27개를 통과했다.
