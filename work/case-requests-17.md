# 17. 케이스 분석·자문 요청

## 화면 근거와 개발 범위

[참조 PDF](../reference/Techcyte_IMS_Demo_Screen_Analysis.pdf) 32쪽 화면에는 사건별 앱 내·메일·Push 알림 설정이 보인다. 37쪽 화면에는 뷰어에서 요청 유형과 담당자를 선택하는 UI가 나온다. 발표자는 요청에 따른 AI 실행 또는 규칙 기반 선실행을 설명했다. 이번 개발은 IMS의 로컬 요청·배정·앱 내 알림과 완료 결과 참조를 구현했다. 외부 알림 발송, 모델 자동 실행, 최종 보고·LIS 전송은 연동하지 않았다.

베이스 저장소에서 `d3741bc`를 확인했다. 현재 IMS의 인증과 케이스 배정 정책, WSI 타일 뷰어, 기존 PD-L1 스냅샷 조회·검증 규칙, `clinical_events`를 재사용했다.

## 개발 환경 권한과 상태

| 주체 | 기능 |
|---|---|
| 기관 관리자 | 기관 케이스의 요청 등록·배정·재배정·취소, 실패 후 다시 열기, 완료 결과 참조 |
| 현재 케이스 담당 병리의 | 요청 등록, 자신이 등록한 요청 관리, 케이스의 요청·완료 결과 참조 |
| 요청 담당자 | 본인 요청 열기·처리 시작·완료·실패 기록. 지정된 스캔을 배정·처리 중인 동안 읽기 전용으로 열기 |
| 그 외 계정 | 기관 경계와 기존 케이스 권한 적용. 다른 사용자 Inbox 열람 차단 |

- 자문 담당자는 기관의 활성 병리의 중에서, AI 요청 담당자는 활성 병리의 또는 관리자 중에서 선택한다. 요청 담당자가 일반 케이스 접근 권한을 갖지 않은 경우 요청에 포함된 스캔과 업무 내용만 조회할 수 있다. 환자 정보, 주석·측정 저장 및 별도 케이스의 파일에는 기존 권한을 적용한다.
- 상태 전이는 **배정 대기 → 배정됨 → 처리 중 → 완료/실패**다. 실패 시 사유를 저장하고 **다시 요청**으로 미배정 상태로 돌릴 수 있다. 재배정은 처리 시작 전에 허용하며, 완료·취소 상태는 닫힌다. 케이스 담당자와 검토 상태는 별도로 관리한다.
- 앱 내 알림은 상태 변경 트랜잭션에서 요청자와 담당자에게 기록한다. 배정에서 제외된 계정은 종료 사실을 받고, 처리 권한을 잃은 요청의 상세 링크는 결과에 포함하지 않는다. 읽음 상태는 계정별로 저장하며 새 알림은 10초마다 조회한다. 알림함에는 읽지 않은 항목부터 최대 50건을 표시한다.
- 자문 완료에는 답변이 필요하다. PD-L1 분석 완료에는 해당 기관과 스캔에서 식별한 기존 보관 스냅샷이 필요하다. 초안 참조에는 완료된 요청의 답변이나 스냅샷 ID, 모델·분석 버전을 표시한다. WSI 링크는 선택한 스냅샷을 지정하며, 스냅샷이 없으면 화면에서 이를 표시한다. 수치와 세포 오버레이는 기존 PD-L1 화면에서 기존 표시 규칙을 적용한다.

## 구현과 마이그레이션

- API와 데이터 모델은 `backend/app/case_requests.py`, `models.py`, `main.py`에 있다. WSI와 PD-L1의 공통 스캔 확인 로직을 재사용한다. 요청 생성은 기관·요청자·Idempotency-Key로 중복을 막고, 내용이 다른 재사용은 409를 반환한다. 상태 변경은 요청과 케이스를 잠그고 예상 버전을 확인한다. 감사 이벤트와 알림은 같은 트랜잭션에서 추가하며 알림은 요청·이벤트 버전·수신자 조합으로 중복을 막는다.
- 케이스 상세와 WSI에 연결한 UI, 요청 처리 화면, 인앱 알림함, 보고 초안 참조는 `frontend/src/case-requests.tsx`와 기존 화면 컴포넌트에 있다.
- Alembic `0007_case_requests`는 `case_requests`와 `request_notifications`를 추가한다. 되돌릴 때는 개발 DB에 먼저 백업을 남기고 개발 환경의 `backend`에서 `python -s -m alembic downgrade 0006_worklist_views`를 이전 코드와 함께 적용한다. 롤백 시 요청과 알림 테이블은 제거된다. 공유 감사 이력 테이블의 기존 레코드는 유지되며, 0007에서 생성된 요청 감사 이력도 남는다. 완전한 이전 시점 복원이 필요하면 사전 백업을 사용한다.

## 검증과 재현

검증 환경은 Linux 6.8, Conda Python 3.10.20, Node 22.12.0, PostgreSQL 18.6, Chrome 146이다. 브라우저 검증에는 저장소의 예제 WSI와 격리 DB의 합성 계정·업무 데이터를 사용한다. 테스트가 가져오는 PD-L1 결과 원본과 수정본도 합성 데이터다.

```bash
MEDIAUTO_PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs scripts/verify-integration.sh
```

수동 재현은 **케이스 상세 → 요청 → 새 요청 → 담당자 배정 → 담당자 계정 요청 알림 → 처리 시작 → 처리 완료 → 보고 초안 참조** 순서다. 파일에서 묶은 케이스는 **등록 파일로 케이스 확정**을 먼저 실행한다. AI 요청은 동일 스캔에 보관 결과가 있어야 완료할 수 있다. 데이터 모델과 권한은 개발 시연 기준이며 실제 병리과 사용자 검토는 미실행이다.
