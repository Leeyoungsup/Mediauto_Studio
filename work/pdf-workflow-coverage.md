# Techcyte IMS PDF 전체 워크플로우 구현 기준

아래 표는 구현 계획 당시의 기준이다. 최신 결과는 [42번 통합 검증](workflow-verification-42.md)과 [34개 화면·96개 기능 ID의 결과](workflow-feature-matrix-42.md)에서 확인한다.

**범위** — [참조 PDF](../reference/Techcyte_IMS_Demo_Screen_Analysis.pdf) 47쪽 전체. 요약·업무·연동 설명은 2–13쪽, 대표 화면 34개는 14–47쪽이다. 기존 01–18에서 만든 기능은 시작점으로 사용한다. 아래 번호는 빠진 단계마다 구현·디버깅·검증을 따로 지시하기 위한 것이다.

## 업무 흐름

1. **유입·접수·QC** — 스캐너와 LIS/EMR에서 식별자·상태를 받거나 파일명 규칙·수기 입력으로 등록 → 환자·케이스·검체·스캔 대조 → 라벨·스캔 QC와 이상 처리 → 기관별 Worklist.
2. **업무 분류·배정** — 역할별 Worklist → 케이스·환자·검체·담당자·스캔 상태·LIS 상태 필터 → 저장 View·정렬·컬럼 → 분야·그룹·Frozen 같은 분류 → 배정·재배정과 세부 상태.
3. **판독과 임상 맥락** — Tray의 정확한 스캔 선택 → WSI·환경설정 → 임상 History·Media·Gross 확인 → 필요한 메타데이터 편집 → 다중 WSI 비교·주석·측정·계수·캡처 → 감사 이력.
4. **분석·자문·협업** — 수기 또는 규칙 요청 → 담당자·상태·알림 → 외부 또는 내부 AI 결과 조회 → 원본·수정본·버전과 근거 확인 → ROI 유사검색, 공동 판독, Tumor Board.
5. **분야별 판독과 보고** — 일반 판독·IHC·PD-L1·전립선·흑색종·Pap 또는 동결절편 경로 → 기록과 검토 → 보고 템플릿·근거 참조 → 동결절편 예비보고와 OR 콜백 또는 일반 보고 승인과 LIS 전달 → 전송·정정·감사 확인.

업무 흐름은 샘플 데이터와 기관 시스템 미설정 상태에서도 검증한다. 여러 기능이 연결되는 최종 시연은 분야별로 수행한다. 케이스 상태, 슬라이드 상태, QC 상태, 보고 상태, 연동 전송 상태는 각각 원천과 갱신 규칙을 정의한다.

## 대표 화면 밖의 항목과 근거

- **PDF 화면·구성도** — AP/CP 플랫폼 구성도에 스캐너, LIS/EHR, PACS/VNA와 HL7/FHIR/DICOMweb이 표시된다. QC 선택과 열람·변경 기록도 요약에 나타난다. 조직별 입출력과 운영 경로는 **21·25·41**에 반영한다.
- **업체 설명** — 업무량 점수·구독형 업무함, OCR, IHC 판정·best block, 음성 전사·보고 템플릿, 사전 AI 실행, 외부 AI, Teams, 최대 6분할과 자동/수동 정합, 운영 배포·보존·버전 병행이 언급된다. 각각 **20·21·26·27·29·31·33·41**에 넣었다. 실제 기관 인터페이스, 모델, 데이터·권한과 계약 자료에서 적용 범위를 검증한다. 자료에 서술된 CP 플랫폼 범위 중 독립 업무 순서가 확인되지 않은 부분은 **41**에서 기관 사용자와 정의한다.
- **회의 참석자 의견** — 병리의 판독과 병리사 운영 업무를 함께 관찰할 필요성, CPS·TPS 동시 지원 요구가 언급된다. 실제 사용자 검토와 모델 검증 과제로 이어진다. [10번 시연 기록](integration-demo-10.md)에는 실제 임상 사용자 평가 결과가 아직 없다.
- **자체 개발 제안** — 19–42의 번호, 선행 의존성과 검증 기준은 IMS 구현 계획이다. 업체에 관한 수치, 가격·일정, 규제 주장, 발표된 실제 병원 연동은 기관 계약·검증 자료와 대조한다. 진단·점수 산출, 환자 매칭, 보고 승인·전송은 연동·임상 계약 확인 후 적용한다.

## 실행 순서와 통합 시연 기준

| 묶음 | 명령 | 연결을 확인할 시나리오 |
|---|---|---|
| 접수·업무함 | 19 → 20 → 21 | EMR/LIS 미설정과 Mock 각각에서 파일 접수→대조→QC→검색·우선순위→배정. 동결절편 Worklist 항목과 상태 원천을 확인한다. |
| 판독과 케이스 맥락 | 22 → 23 → 24 → 25 → 26 | 스캔 구분→판독→임상 이력·첨부→읽기·변경 이력→댓글·알림. 스캔·첨부 손상과 권한 회수도 검증한다. |
| 보고·동결절편 | 27 → 28 | 일반 케이스 보고 작성·승인·수신 확인과 동결절편 우선순위→예비보고→OR 전달·콜백의 두 경로를 검증한다. |
| 뷰어·분석·협업 | 29 → 30 → 31 → 32 → 33 | ROI·판독 도구→계수·내보내기→분석·자문→보드·공동 판독에서 권한과 원본 추적을 검증한다. 32·33은 30의 외부 검색 자료 없이 개발할 수 있다. |

각 명령의 결과는 코드, 자동 검증, 기관·임상 검토를 구분해 기록한다. 전체 커버리지 완료는 34개 화면과 96개 기능 ID 각각의 검증 결과, 외부 자료 대기 및 사유를 확인한 뒤 판단한다. 현재 산출물은 대조표와 작업 명령이다. 서비스·DB 변경과 E2E 재실행은 이번 계획 작업에 포함하지 않았다.
