# 10번 첫 통합 시연 검증

2026년 11월 24일 개발 환경에서 자동 검증과 별도 브라우저 화면 점검을 수행했다. 개발 기능 검증은 통과했다. 병리과 사용자가 참여한 임상 사용성 평가는 미실시다.

## 범위와 변경

- 참조 PDF 14–22쪽의 Worklist와 슬라이드 Tray, 23–29쪽의 뷰어와 케이스 정보, 30쪽의 Case logs를 기준으로 점검했다. 화면에서 관찰된 업무 경로를 검증에 사용했다. 제품 발표 설명과 회의 의견은 판정 기준에서 제외했다.
- WSI 경로는 08번에서 연결한 베이스 `d3741bc`의 Canvas 좌표계와 JPEG 타일 규격을 사용했다. 인증·배정·추가 전용 감사 이력은 07·09번의 기존 구조를 사용했다.
- 검토 단계 창에 선택 입력인 **검토 메모**를 추가했다. 변경 사유와 메모는 같은 검토 이벤트에 저장한다. 메모 최대 길이는 2,000자다. 케이스 **기록**에서 상태 전이와 사용자, 시각, 사유, 메모를 확인할 수 있다. DB 스키마는 기존 리비전 `0003_auth_worklist`를 사용한다.

## 실행 결과

| 시나리오 | 판정과 관찰 |
| --- | --- |
| 관리자 로그인 → Case ID 검색 → 배정 | PASS. 소문자 검색어로 케이스를 찾았고 담당 병리의 Worklist에 배정이 반영됐다. |
| 담당 병리의 로그인 → 내 배정 건 → 실제 NDPI/SVS | PASS. 두 형식에서 Canvas 픽셀과 JPEG 타일 응답을 확인했다. 별도 브라우저 조작으로 Tray, 확대, 미니맵, 스케일바를 확인했다. |
| 검토 시작 → 완료와 메모 저장 → 로그아웃·재로그인 | PASS. 상태와 메모가 복원됐다. 별도 브라우저에서도 기록 탭에서 메모, 상태 전후 값, 계정과 시각을 직접 대조했다. |
| EMR 미설정과 환자 정보 없음 | PASS. `unconfigured` 상태에서 배정, WSI, 검토 저장이 완료됐다. |
| 잘못된 비밀번호와 권한 실패 | PASS. 잘못된 비밀번호 1회 후 재로그인. 비로그인 타일 401, 미배정 계정의 케이스·타일 조회 404, 병리의 계정의 배정 변경 403. |
| 검색 결과 없음과 스캔 누락 | PASS. 빈 결과 화면, 스캔 없는 케이스의 뷰어 버튼 비활성, 검토 전이 409를 확인했다. |
| 타일 장애와 재시도 | PASS. 타일 503을 주입하자 실패 안내가 표시됐다. 장애 해제 후 1회 재시도로 JPEG가 들어왔고 배율과 미니맵 영역이 유지됐다. |
| 손상·변경·누락 파일과 동시 수정 | PASS. PostgreSQL 테스트에서 손상 422, 변경 409, 파일 누락 404를 확인했다. 같은 버전의 변경 요청 중 한 건만 저장됐다. |

프런트 빌드, `alembic check`, PostgreSQL 테스트 10개, Playwright 통합 시나리오가 통과했다. 수동 화면 점검은 에이전트가 자동 스위트와 다른 Chrome 세션에서 스크린샷을 보며 클릭·입력·휠을 조작했다. 잘못된 비밀번호 안내와 정상 로그인 복귀, 스캔 누락 화면의 뷰어 비활성도 수동으로 확인했다. 실제 임상 사용자의 독립 수행이나 의견 수집은 미실시다.

## 업무 사용성 측정

정상 시나리오의 자동 조작 시간을 역할별로 한 번 기록했다. 입력란 하나 입력, 클릭, 선택, 휠 제스처 또는 드래그를 각각 1회로 계산했다. 화면 전환은 로그인 → Worklist → 케이스 상세 → 뷰어를 세었다. 목록 내 탭, 모달, Tray 전환은 화면 전환 수에서 제외했다. 시간에는 입력과 렌더링을 포함하며, 사람의 읽기·판단 시간이나 병원망 지연은 포함되지 않는다.

| 역할과 완료 지점 | 조작 수 | 화면 전환 | 경과 | 정상 오류 / 재시도 |
| --- | ---: | ---: | ---: | ---: |
| 관리자 로그인부터 배정 저장 반영까지 | 9 | 2 | 0.842초 | 0 / 0 |
| 담당 병리의 로그인부터 두 스캔 열기와 검토 완료 저장까지 | 24 | 3 | 2.979초 | 0 / 0 |

| 성능 항목 | 결과 |
| --- | --- |
| 로그인 입력 시작 → Worklist 응답 | 관리자 486ms, 병리의 336ms |
| 케이스 상세 → 첫 NDPI 픽셀 표시 | 366ms |
| NDPI → 첫 SVS 표시 | 264ms |
| 같은 케이스에서 Tray 교대 선택 5회 | NDPI 중앙값 276ms, 범위 269–861ms. SVS 중앙값 264ms, 범위 258–275ms |
| 확대·팬 반응 | 휠 확대 입력부터 배율 갱신 36ms, 드래그 시작부터 미니맵 영역 갱신 73ms |
| 주입 장애 재시도 | 로그인 1회, 타일 1회 |

수동 관찰에서 케이스 상세와 Tray는 같은 슬라이드 번호의 NDPI와 SVS를 형식명으로 구분한다. Worklist 미리보기 카드는 같은 슬라이드 번호만 보여 형식 구분을 상세 또는 Tray에서 확인해야 했다. 검토 창에서 변경 사유와 검토 메모는 별도 입력란으로 표시됐고, 기록 탭에서 각각 대조할 수 있었다.

임상 사용자 평가 시에는 관리자 또는 배정 담당자와 병리과 의사가 같은 합성 시나리오를 맡는다. 작업 완료율, 올바른 환자·케이스·스캔 선택 여부, 완료 시간, 조작·전환 수, 오류·재시도, 도움 요청, 사용자 의견을 역할별로 기록한다. 사용자 합의에 따른 기준값, 병원망이나 다중 사용자 성능, 임상적 검토와 색상·길이 교정은 아직 평가하지 않았다.

## 재현

프로젝트 루트에서 아래 명령을 실행한다. 테스트 계정과 케이스는 별도 PostgreSQL에 생성된다. 기존 개발 DB와 시연용 원본 스캔은 보존된다.

```bash
test_deps=$(mktemp -d /tmp/mediauto-test-deps.XXXXXX)
npm install --prefix "$test_deps" playwright-core@1.56.1
export MEDIAUTO_PLAYWRIGHT_MODULE="$test_deps/node_modules/playwright-core/index.mjs"
scripts/verify-integration.sh
```

별도 화면 점검은 `scripts/verify-integration.sh --manual`을 실행하고 터미널에 표시된 루프백 주소를 연다. 기관은 `local`이다. 격리 테스트 계정은 `integration-admin`, `integration-doctor`, `integration-other`이고 비밀번호는 모두 `synthetic-test-password`다. `IMS-DEMO-101`의 배정과 검토를 수행하고, 스캔 누락 예외는 `IMS-DEMO-NO-SCAN`에서 확인한다. Enter로 세션을 종료한다. Chrome 실행 경로와 테스트 포트는 `MEDIAUTO_CHROME`, `MEDIAUTO_DEMO_PORT`로 바꿀 수 있다.
