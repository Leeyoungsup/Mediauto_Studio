# 25. Case Logs

## 범위와 근거

- **화면 관찰**. PDF 30쪽에서 Time, User, Action, Entity, Result 열과 스캔 열람·주석 생성·삭제 이력을 확인했다. [참조 PDF](../reference/Techcyte_IMS_Demo_Screen_Analysis.pdf)
- **발표 설명**. 케이스와 주석의 변경 추적 및 버전 관리의 중요성이 설명됐다.
- **참석자 의견**. 기관별 접근 권한, 보존 기간과 법적 감사 요건의 확정 기록은 확인되지 않았다.
- **IMS 구현 결정**. 기관 관리자와 현재 케이스에 배정된 병리의가 Case Logs를 조회한다. 파일 등록 그룹은 임상 케이스로 확정한 뒤 사용할 수 있다. 기존 Case History에는 기존 방식대로 케이스 변경 내역을 표시한다.

## 사용 방법과 범위

1. **Case Details** 또는 **WSI Viewer**에서 **Case Logs**를 연다. **User**, **Action**, **Entity**, **Result**를 조합하고 **Apply Filters**를 누른다. 특정 객체는 **Target ID**에 상세에 나온 UUID를 입력한다.
2. **View Details**에서 변경 사유와 전후 값을 확인한다. WSI의 **Review Position and Annotations**에서 **Edit Name**으로 주석 이름을 바꿀 수 있다. 작성자와 관리자가 수정·삭제할 수 있다. 이름 수정 시 최신 버전을 확인한다.
3. 케이스 열람과 WSI 최초 표시, 첨부 첫 페이지와 임상 기록 열람을 추가했다. WSI 열람 결과는 캔버스가 이미지를 그린 뒤 클라이언트가 보고한다. 렌더링 완료 전에 닫은 창은 열람으로 집계하지 않는다. 최초 열기 실패, 권한 거부와 재시도는 시도 단위로 구분한다.
4. 승인된 케이스·스캔·검체 작업의 HTTP 실패와 거부를 케이스에 귀속할 수 있을 때 기록한다. 저장된 분석 요청 실패와 구조 QC 실패도 조회한다. 서버가 처리한 HTTP 실패에는 HTTP 상태와 대상 UUID를, 클라이언트의 렌더링 실패에는 대상 UUID와 실패 결과를 기록한다. 감사 범위는 인증된 케이스 작업이며 타일, 로그인 실패와 전역 장애는 별도 운영 로그의 범위다.

## DB와 롤백

- `0014_case_logs`는 조회·실패·거부 이벤트용 `case_activity`와 새 임상 이벤트의 케이스 귀속용 `clinical_events.case_id`를 추가한다. 기존 임상 변화 이벤트와 합쳐 시간·ID 커서로 페이지를 조회한다. 기존 Canvas와 타일 경로는 베이스 `d3741bc`에서 이어진 구현을 사용한다.
- 변경 성공은 기존 트랜잭션의 임상 감사 이벤트를 재사용한다. 주석은 같은 저장 ID를 재전송해도 생성 이벤트가 한 건이며, 두 번째 삭제는 변경을 추가하지 않는다. 실패는 원래 변경의 롤백과 별도 트랜잭션에 기록한다. 인증된 같은 기관에서 귀속 가능한 시도만 추가한다.
- 배포 이전에는 케이스·스캔 열람 및 실패 수집이 없었고 소급 생성하지 않는다. 기존 주석 변화는 저장된 스캔 지문이 현재 케이스와 일치하면 표시한다. 케이스 귀속이 없는 과거 로그에서 슬라이드가 재연결된 기록은 잘못 귀속될 수 있으므로 조회에서 제외한다. 새 주석 변경은 당시 케이스를 고정해 슬라이드 이동 뒤에도 기존 케이스에 남는다.
- 앱의 감사 경로는 추가 전용이다. 기관별 보존·삭제 절차와 DB 운영자 권한 통제는 별도 결정이 필요하다. 롤백은 DB 백업과 이전 앱 코드 준비 후 `cd backend && python -s -m alembic downgrade 0013_case_attachments`로 실행한다. 새 런타임 이력과 케이스 귀속 열이 제거되며 기존 임상 이벤트 행은 보존된다.

## 검증

- 격리 DB에서 `0013 → 0014 → 0013 → 0014`, Alembic 스키마 일치와 기존 케이스·설정 보존을 확인했다.
- 9920 개발 DB에 `.runtime/before-case-logs-0014-20261124T180453.dump`를 만든 후 적용했다. 기존 임상 이벤트, 환자·케이스·검체, 설정 건수와 설정 지문을 비교했다. 개발 서버에는 등록 임상 케이스가 없어 배포된 경로와 접근 응답을 확인하고, 화면 시나리오는 격리 합성 케이스에서 검증했다.
- Linux, Node 22.12.0, PostgreSQL 18.6, Chrome 146에서 합성 케이스와 WSI 예제를 사용했다.
- `MEDIAUTO_DEMO_PORT=19925 scripts/verify-integration.sh` **PASS**. Playwright와 Tesseract 경로를 지정해 빌드, PostgreSQL/API 테스트 26개, Chrome 시나리오 12개를 통과했다. 사용자가 WSI를 열고 실패 후 재시도하는 흐름, 주석의 변경 전후, 필터 조합과 거부 응답을 확인했다. API에서 중복, 페이지 경계, 슬라이드 이동 전후의 귀속과 기관 격리를 확인했다.
- 임상 사용자 검토와 명령표의 사용자 확인은 대기 중이다.
