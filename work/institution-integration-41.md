## 식별자·상태 원천 제안

| 상태/데이터 | 권위 원천과 IMS 처리 |
|---|---|
| 환자 정보와 환자 ID | 기관 지정 EMR 또는 환자 인덱스. `기관 + 원천 시스템 + 발급기관/식별자 종류 + 원문 값`으로 구분한다. 로컬 환자 UUID는 유지하고, 연결 후보·충돌·환자 병합/정정은 이전 연결과 출처를 남긴 뒤 승인한다. 이름·MRN 문자열만으로 병합하지 않는다. |
| AP 접수·검체/블록/슬라이드·외부 케이스 상태 | 기관 AP LIS. 내부 케이스·검체·슬라이드 UUID와 외부 식별자 매핑을 보존한다. 외부 상태 원문, 매핑 버전, 원천 리비전·시각, 마지막 수신 시각을 유지한다. 상태 미수신과 원천 장애를 구별한다. |
| 스캔 완료·교체·QC | 스캐너가 획득·완료·실패 원천이다. 동일 슬라이드 재스캔은 새 스캔과 선행 스캔 관계로 보존한다. 장비·AI QC와 IMS 사람 검토의 판정·조치·시각은 각각 기록한다. |
| IMS 배정·판독·내부 승인 | IMS 상태 이력과 승인 리비전이 원천이다. LIS 상태·스캔 완료·아카이브 상태는 독립 열로 유지한다. IMS의 `reviewed`는 내부 검토 상태다. |
| 외부 보고 수락·게시 | LIS의 업무 ACK와 게시/정정 상태 조회가 원천이다. 전송 시도, 전송 계층 수신, 업무 ACK, 게시 확인을 각각 검증한다. |
| 보관·열람·철회 | PACS/VNA가 보관·장애·만료/철회 상태를 제공한다. 검색 결과와 실제 인스턴스/프레임 재조회 증거를 각각 남긴다. UID 중복, 동일 UID의 콘텐츠 충돌, 원본과 재처리본의 계보를 확인한다. |
| CP 오더·관찰 결과 | 기관에서 지정할 LIS·미들웨어. 기기 측 결과 발생과 LIS의 임상 검증·정정, EMR 게시 상태의 권한과 시점을 따로 합의한다. |

## 버전·ACK·장애 계약

- **버전.** 장비 모델·펌웨어, 시스템 릴리스, 기관 인터페이스 명세/프로파일, IMS 매핑·어댑터 릴리스를 각각 고정한다. 메시지 ID는 중복 판별에, 원천 리비전은 데이터 변경 판별에 사용한다. 현재 Mock은 증가 정수의 스냅샷 리비전을 사용한다. FHIR을 채택할 경우 `meta.versionId`를 원천이 발행한 불투명 값으로 보존하고 최신본/정렬 규칙을 별도 계약한다. 지원 종료와 업그레이드 전·후 샘플, 양쪽 버전 공존 여부, 롤백 버전을 기록한다. [FHIR R4 HTTP](https://hl7.org/fhir/R4/http.html)
- **상관관계.** HL7 v2를 채택하면 원본 `MSH-10`과 ACK `MSA-2`를 송신 기관·채널과 함께 대조하고 `MSA-1` 및 상세 오류에 따른 수신·업무 ACK와 재시도 조건을 합의한다. 현재 Mock 전송에는 보고 전송 UUID, payload digest와 ACK ID를 사용한다. [HL7 MSH 매핑](https://hl7.org/fhir/uv/v2mappings/ConceptMap-segment-msh-to-messageheader.html), [HL7 MSA 매핑](https://www.hl7.org/fhir/uv/v2mappings/ConceptMap-segment-msa-to-messageheader.html)
- **중복·충돌·순서.** 동일 식별자와 동일 내용은 재수신으로 처리한다. 동일 식별자와 다른 내용, 문서/스캔 식별자 미매칭, 늦게 도착한 정정 또는 오래된 새 이벤트는 각각 수락 여부와 운영자 처리 기준을 정한다. 승인된 현재 데이터와 기존 감사 이력을 보존한다.
- **장애와 복구.** 기관별 타임아웃·처리 한도·재시도·알림 책임자와 장애 중 조회 가능한 정보의 신선도 표시를 확정한다. EMR/LIS 장애 중에는 수기 환자, 로컬 케이스·판독과 등록된 로컬 스캔을 사용한다. 스캐너/PACS가 복구되면 누락 분량을 대사하고 보관·수신 결과를 다시 읽는다. 외부 게시 여부가 불명확한 보고는 원천과 대사한 뒤 동일 식별자로 재처리한다.
- **현재 Mock 동작.** 수신 타임아웃은 최초 시도 포함 최대 4회 후 `dead_letter`로 이동한다. 보고 ACK 불일치는 최대 3회 후 `failed`로 이동하고 명시적 재처리를 지원한다. Mock 설정을 꺼도 이미 저장된 기록은 남는다. 비활성화 뒤 아직 작업자가 가져가지 않은 보고는 `adapter_disabled`로 실패할 수 있다. 기관 연동 시에는 진행 중 전송을 별도로 대사하고 미전송 큐의 보류·재개 절차를 시험해야 한다. [수신 구현](../backend/app/integration_service.py), [보고 전달 구현](../backend/app/report_delivery.py)

## 승인 환경 수락 시험

기관 테스트 환경으로 전환하기 전에 기관 연동 담당자, 병리 AP/CP 책임자와 보안 담당자가 **시스템별 제품·버전, 시험 테넌트와 엔드포인트 참조, 연결 방향, 계정 및 허용 작업, 실제 인터페이스 명세, 샘플 데이터 범위**를 확정한다. 자격 증명은 승인된 비밀 저장소를 사용한다. 스캐너·LIS·PACS의 쓰기 시험은 항목별로 허용된 경우에만 수행한다.

| 시험 | 기관 시험 상태와 필요한 증거 |
|---|---|
| 네트워크·인증 | **NOT RUN** · 승인된 포트·방화벽/ACL·TLS 신뢰 및 계정 접근 범위, 소스·목적지 식별과 환경 분리 증거 |
| AP 스캐너 및 PACS/VNA | **NOT RUN** · 합성 바코드/WSI로 완료·부분 파일·재스캔과 중복·손상, 일치하는 아카이브 UID/프레임 조회, 정해진 장애·복구 후 재조회 |
| EMR/LIS 수신·대사 | **NOT RUN** · 기관별 비식별 예제 메시지로 필드/버전·비호환·중복·순서·정정·환자 충돌, 동일 데이터에 대한 원천 조회 및 역할별 감사 대조 |
| LIS 송신·ACK·게시 | **NOT RUN** · 승인된 합성 보고·정정, 대응 ACK ID/오류·누락·지연·중복, 업무 수락과 실제 게시의 대응, 권한 없는 송신 거부 |
| CP | **NOT RUN** · CP 책임자가 승인한 검사군의 오더·검체·결과·단위·정정 왕복과 이상 플래그 검증 |
| 롤백·장애·보존 | **NOT RUN** · 커넥터 비활성화, 새 송신 중단, 진행 중 전송의 원천 대사, 로컬 업무 유지, 서명된 보존 기준과 복원 후 상태·감사 검증 |
