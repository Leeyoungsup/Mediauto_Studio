# 24. 케이스 Media와 검체 Gross Images

## 범위와 근거

- **화면 관찰**. PDF 26쪽 Media에는 케이스에 첨부된 문서 열람 영역이 있고, 27쪽 Gross images에는 육안사진 탐색 화면이 있다. [참조 PDF](../reference/Techcyte_IMS_Demo_Screen_Analysis.pdf)
- **발표 설명**. 발표자는 문서 스캐너, PDF 주석·다운로드·출력을 언급했고, 육안사진은 저장소에서 가져오거나 직접 올릴 수 있다고 설명했다.
- **참석자 의견**. 파일 크기, 역할별 권한, 원본 보존 형식, 외부 장비 연동 방식은 해당 화면 설명에서 확정되지 않았다.
- **IMS 구현 결정**. 이 단계의 입력 경로는 파일 업로드다. 독립 PDF 페이지 미리보기와 다운로드, 검체별 육안사진 등록·열람과 다운로드를 구현했다. 기존 `d3741bc` 기반 WSI, 케이스 접근 범위, 임상 감사 이력을 재사용했다. 장비·외부 저장소 연결, PDF 주석과 출력 정책은 별도 범위다.

## 등록과 열람

1. 등록된 임상 케이스의 **Case Details → Media** 또는 **WSI Viewer → Media**에서 **Attach PDF**를 누른다. 목록에서 문서를 선택하고 **Previous Page / Next Page**로 확인한다.
2. **Gross Images → Add Gross Image**에서 **Target Specimen**을 선택하고 JPEG 또는 PNG를 올린다. **Filter by Specimen**에서 같은 케이스의 검체별로 확인한다.
3. **Download Attachment**에서 등록된 파일을 받는다. **Attachment Activity**에는 등록과 다운로드 요청의 수행자와 시각이 표시된다. 뷰어에서 첨부 창을 닫으면 열어 둔 캔버스로 복귀한다.
4. 관리자, 등록 담당자, 해당 케이스에 배정된 병리의가 업로드할 수 있다. 기존 케이스의 조회 권한이 있는 참관 계정은 열람·다운로드할 수 있다. 파일 등록 단계의 임시 케이스는 임상 케이스 확정 후 이 기능을 사용한다.

## 데이터와 검증 한도

- PDF는 케이스, 육안사진은 같은 기관·케이스의 검체 UUID에 귀속된다. API와 복합 외래 키로 검사한다. 동일 업로드 요청은 식별 키로 재사용하며, 크기·건수 합계는 케이스 잠금 안에서 계산한다.
- PDF 입력 10 MiB·50쪽, 사진 입력 12 MiB·2,400만 픽셀, 케이스별 50개·100 MiB 한도다. PDF는 서명·구문·페이지 수 및 첫 페이지 렌더링을 확인하며 암호화 문서를 거부한다. 후속 페이지는 요청 시 렌더링·검증하며 실패한 페이지를 재시도할 수 있다.
- 사진은 방향을 적용하고 EXIF를 제거한 JPEG로 등록한다. 원본 해상도를 유지하되 JPEG로 재인코딩한다. PDF 다운로드는 등록한 바이트이며, 육안사진 다운로드는 등록된 JPEG다. PDF와 육안사진 미리보기는 최대 변 1,500 px의 별도 이미지로 생성한다. 뷰어의 미리보기는 열람용이다. 장비별 색 재현·촬영 표준은 임상 사용자 검토가 필요하다.
- PDF 처리는 서버의 Poppler `pdfinfo`·`pdftoppm`과 Linux `prlimit`을 사용한다. 처리 시간·주소 공간·동시 실행을 제한한다. 첨부 바이트는 PostgreSQL에 보관하며 내려보내기 전에 체크섬을 비교한다. 감사에는 파일 내용 대신 객체·케이스·행위자·이벤트 시각을 기록한다. 다운로드 감사는 서버가 파일 응답을 제공한 요청을 기록한다.

## 마이그레이션과 검증

- `0013_case_attachments`는 첨부 테이블과 검체 귀속 제약을 추가한다. 이전 버전으로 복구하려면 개발 DB와 첨부 파일을 백업한 뒤 `cd backend && python -s -m alembic downgrade 0012_patient_history`를 실행한다. 이때 새 첨부 테이블의 데이터가 제거된다.
- Linux, Node 22.12.0, PostgreSQL 18.6, Chrome 146, Poppler 22.02.0에서 합성 PDF와 PNG를 사용했다. 격리 DB에서 `0012 → 0013 → 0012 → 0013`, Alembic 스키마 일치와 기존 케이스·설정 보존을 검증했다.
- `MEDIAUTO_DEMO_PORT=19924 scripts/verify-integration.sh` **PASS**. Playwright와 Tesseract 경로를 지정해 프런트 빌드, Alembic 검사, PostgreSQL/API 25개와 Chrome 시나리오 11개를 통과했다. 첨부 API의 최종 육안사진 미리보기·다운로드 바이트 분리도 격리 DB에서 재검사했다. 교차 케이스 차단, 미지원·손상 파일, 용량·건수, 동시 다운로드 감사, PDF 페이지 재시도, 검체 필터와 WSI 복귀를 확인했다.
- 9920 개발 DB를 `.runtime/before-attachments-0013-20261124T175324.dump`에 백업한 뒤 마이그레이션을 적용했다. 기존 설정 지문과 환자·케이스·검체·History 등의 건수를 비교했다. 실제 서버에서 로그인·Worklist·첨부 경로를 확인했으며, 등록 임상 케이스의 화면은 격리 환경에서 합성 케이스로 검증했다. 임상 사용자 검토와 명령표의 사용자 확인은 대기 중이다.
