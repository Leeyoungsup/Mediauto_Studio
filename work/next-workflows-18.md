# 18. Tumor Board·공동 판독·Pap 전용 검토 구현 순서

**상태** — 기술 우선순위와 작업 명령 초안. 병리과 사용자 평가와 기관 정책 합의 대기.

## 우선순위 근거

[10번 첫 시연](integration-demo-10.md)에서 개발팀은 로그인, 검색, 배정, NDPI/SVS 읽기, 검토 메모 저장과 재로그인 후 복원까지 확인했다. 자동 조작에서 배정은 9회·화면 전환 2회, 담당 병리의 경로는 24회·화면 전환 3회였다. 첫 NDPI 표시는 366ms, NDPI에서 SVS 전환은 264ms로 관측됐다. 이 값은 같은 서버의 격리 환경에서 나온 개발 기준선이다. 다중 사용자 동시 조작, 병원 네트워크, 실제 사용자의 업무 시간과 판독 의견은 측정하지 않았다. 수동 점검에서 Worklist 미리보기만으로는 같은 슬라이드 번호의 NDPI와 SVS를 구분하기 어려웠다. 회의나 공동 판독에서 스캔을 선택할 때는 형식과 스캔 식별자를 표시하고 선택 정확도를 측정한다.

| 권장 순서 | 첫 구현 범위 | 순서를 정한 근거 |
|---|---|---|
| 1. Tumor Board | 같은 기관 안에서 안건 목록, 케이스 참조, 순서, 회의용 메모 | 10번의 케이스 상세·WSI 경로와 17번의 완료 결과 참조를 사용한다. 제한된 기관 내 역할로 권한과 회의 준비 흐름을 먼저 검증할 수 있다. |
| 2. 공동 판독 | 같은 케이스의 두 계정, 단일 Driver, 선택형 Follow, 연결 복구 | 15번에서 같은 브라우저 안의 뷰포트 동기화를 검증했다. 두 브라우저 간 권한과 지연, 연결 복구는 별도 검증이 필요하다. |
| 3. Pap 전용 검토 | 합성·승인된 비식별 후보 갤러리, WSI 위치 확인, 검토자별 초안·이력 | 범용 뷰어는 재사용할 수 있다. 후보 데이터 계약, 세포검사 담당자·병리의 역할, 검사실 분류와 검토 규칙이 필요하다. 실데이터와 검토자가 확보되면 다른 작업과 독립적으로 탐색할 수 있다. |

참조 PDF에서 확인한 화면은 19쪽 Tumor Board 컬렉션에 케이스와 메모를 추가하는 모달, 33쪽 공동 판독의 참여자와 Follow 초대 메뉴, 45~47쪽 Pap 후보 갤러리·결과 입력·연관 조직생검 창이다. 발표자는 케이스 참조를 컬렉션에 추가하는 방식, 진행권 교대와 Teams 연동, Pap의 검토자별 Review를 설명했다. 회의 참석자의 의견은 요구사항 승인 근거로 사용하지 않았다. 위 순서와 각 첫 구현 범위는 이 프로젝트의 제안이다. 세 명령은 현재 IMS에 각각 연결하는 독립 작업이다. 각 명령의 검증은 합성 기관·계정으로 시작할 수 있다. 임상 사용성 합격 기준값과 기관별 권한 정책은 사용자 검토 후 확정한다. 현장 요구에서 원격 자문의 빈도나 긴급성이 더 높다면 1·2의 순서를 바꿀 수 있다. Pap은 승인 데이터와 역할·분류 계약이 확보되면 별도로 착수할 수 있다.

## 18-1. Tumor Board 안건 준비

> **18-1 진행.** 같은 기관의 Tumor Board 목록과 회차별 안건을 만들어줘. 회의 코디네이터가 Worklist에서 케이스 참조를 추가하고 순서·회의용 메모를 편집하게 해줘. 참석자는 권한이 있는 안건에서 케이스 상세, WSI, 완료된 자문·AI 참조를 열 수 있게 해줘. 중복 추가, 동시 메모 수정, 다른 기관과 비참석자 접근, 참석 권한 회수, 원본 케이스 조회 권한이 없는 사용자를 E2E로 검증해줘. 회의 준비 시간과 조작·전환 수, 정확한 케이스·스캔 선택 여부를 기록해줘.

- **권한 제안** — 기관 관리자가 코디네이터와 참석자를 지정한다. 코디네이터는 회차와 안건 참조를 관리한다. 참석자에게는 기존 케이스 조회 권한을 교차 적용한다. 접근 불가 케이스는 목록, 개수, 검색, 상세 링크 응답에서 노출하지 않는다. 케이스 상태나 담당자 변경은 기존 흐름에서 수행한다.
- **검증 기준** — 중복 추가는 같은 안건 하나로 수렴한다. 편집 충돌은 표시하고 원본을 보존한다. 재접속 후 안건 순서·메모가 복원된다. 참석 권한을 회수하면 이전 Board 링크의 접근이 차단된다. 원본 케이스 권한을 회수하면 해당 케이스 상세와 타일 접근도 차단된다. Chrome에서 코디네이터와 참석자 계정을 오가며 안건 등록부터 WSI·완료 결과 확인까지 검증한다.
- **외부 의존성** — 같은 기관 코디네이터와 회의 참석자의 시나리오 검토. 타과·외부 기관 접근과 외부 시스템 연계는 해당 기관의 계정·공유 정책이 필요하다.

## 18-2. 공동 판독 세션

> **18-2 진행.** 기존 WSI에 같은 기관·같은 케이스의 두 계정이 참여하는 공동 판독 세션을 붙여줘. 케이스 열람 권한을 확인하고, Driver 한 명의 스캔·중심 좌표·배율을 Follow를 선택한 참석자에게 동기화해줘. Follow 해제, 진행권 인계, 네트워크 단절 후 재접속과 권한 회수를 구현해줘. 두 브라우저에서 좌표·배율 오차, 입력부터 반영까지의 지연, 재접속 시간과 횟수, 진행권 인계 조작 수를 기록해줘.

- **권한과 흐름 제안** — 세션 진행자가 기존 케이스 열람 권한이 있는 계정을 초대한다. 참석자는 Follow를 켜거나 끄고, 명시적 인계 후에만 Driver가 바뀐다. 서버가 허용한 최신 스캔 ID와 level-0 좌표·배율을 사용한다. 세션 참여·인계·종료 이력을 남긴다.
- **검증 기준** — 다른 기관·미권한 계정의 참여와 재접속을 차단한다. 동시에 인계를 시도해도 Driver는 한 명이다. 서로 다른 뷰포트 크기, NDPI/SVS 전환, 순서가 뒤바뀐 이벤트, 단절 후 최신 프레임 복원, Follow 해제 후 로컬 뷰 유지와 세션 종료를 검증한다. 지연은 개발 환경과 지연·손실 주입 조건의 중앙값·p95를 각각 기록한다.
- **외부 의존성** — 병원망의 연결 유휴 시간과 접근 제어, 역할별 사용자 평가. 초기 시험은 같은 케이스의 단일 뷰에서 한다. 음성·영상 통화와 공동 주석 쓰기는 별도 검토 대상으로 둔다. 15번의 같은 브라우저 내 동기화 결과는 원격 성능 기준으로 사용하지 않는다.

## 18-3. Pap 전용 검토

> **18-3 진행.** 합성 또는 승인된 비식별 Pap 후보 데이터를 쓰는 전용 검토 화면을 만들어줘. 후보–스캔 식별자, level-0 좌표, 범주와 출처·버전의 입력 계약을 작성하고, 후보 갤러리에서 선택한 위치를 기존 WSI에서 확대해줘. 세포검사 1차 검토자와 후속 병리의가 각자 초안·검토 이력을 남기게 해줘. 후보 없음, 좌표 범위 초과, 다른 케이스·스캔의 후보, 동시 저장, 재접속 복원을 검증해줘. 올바른 후보 위치를 고르는 비율, 후보 전환 시간, 저장·재개 성공률, 조작 수와 오류를 기록해줘.

- **권한과 흐름 제안** — 승인된 Pap 검체에만 전용 화면을 표시한다. 후보 원본과 검토자의 판단을 구분해 저장한다. 1차 검토자와 병리의의 기록을 두 계정에서 대조한다. 실제 입력 필드·용어, 필수 여부와 후속 검토 범위는 검사실 정책 확인 후 확정한다.
- **검증 기준** — 기준 좌표가 있는 합성 후보를 선택하면 정확한 스캔·영역이 열리고 확대·재접속 후에도 연결이 유지된다. 잘못된 출처나 좌표는 불러오기 단계에서 거부하고, 빈 결과·미수신·오류 상태를 화면에서 구분한다. 역할별 편집 권한과 동시 수정 시 기존 이력 보존을 검증한다.
- **외부 의존성** — 비식별 후보·스캔·정답 좌표, 검사실의 검체 적절성·해석 항목과 역할 규정, 승인된 모델·버전 및 기준 정답 자료. 실제 AI 후보 누락률과 임상 적합성은 승인된 자료에서 별도 검증한다. Pap–조직생검 비교는 환자 대조·증례 연결 규칙과 양쪽 케이스 권한이 확정된 뒤 별도 작업으로 진행한다.

## 임상 사용자 검토 관문

배정 담당자 또는 회의 코디네이터, 담당·자문 병리의, 세포검사 검토자가 역할별로 합성 증례를 독립 수행한다. 10번에서 정의한 관찰 항목에 맞춰 완료 여부, 올바른 케이스·스캔 선택, 실제 경과 시간, 조작·화면 전환, 오류·재시도·도움 요청, 사용자 의견을 기록한다. 권한 문제가 있었는지와 기능별 추가 지표를 사례별로 함께 남긴다. 검토 결과로 각 첫 구현 범위와 출시 기준을 확정한다. 이번 단계는 계획 검토에 해당하며 코드 변경, 마이그레이션, 기능 E2E, 임상 평가를 실행하지 않았다.
