# AI 세포 오버레이의 전체 표시와 줌 재사용

## 증상과 변경

- 기존에는 512px 단위 조회 경계가 움직일 때 PD-L1과 IHC가 뷰포트 범위를 다시 조회했다. 기존 API는 해당 범위의 목록을 5,000개에서 잘랐다. IHC의 이전 응답은 새 범위와 일치하지 않으면 즉시 사라졌다.
- 이제 결과가 작은 경우 전체 세포 위치를 한 번 받아 화면에서 좌표를 변환한다. 결과가 큰 경우 전체 영역의 클래스별 밀도와 개수를 한 번 받는다. 확대 시 2,048 레벨 0 픽셀 블록의 상세 세포를 가져오며, 큰 블록은 다음 페이지까지 받아 완결한다. 아직 상세 블록이 도착하지 않은 동안 분포를 표시한다.
- 상세 데이터는 현재 스캔·결과·수정본의 캐시에 보관한다. 이미 받은 블록 내의 확대에는 새 요청이 필요 없다. 새 블록이 화면에 들어오거나 결과 버전을 전환하면 해당 데이터가 필요하다. 매우 밀집한 화면에서 세포 표식은 Canvas 래스터로 그린다.
- PD-L1과 IHC(Ki-67, ER, PR, HER2) 표시 경로에 적용했다. 같은 스캔에 여러 분석이 있으면 선택한 결과층을 표시한다. 기존 IHC 임계값과 수기 수정, PD-L1 결과 원천과 점수 계약을 사용한다. DB 마이그레이션은 없다.

## 재현과 검증

- 큰 보관 결과에 연결된 스캔을 **Open Viewer**로 열어 **Detection Results**의 밀도 안내와 분포를 확인한다. 20×로 확대해 상세 셀이 나타나면 40×로 더 확대하고 **Fit to Window**로 돌아온다. 브라우저 Network에서 이미 확보한 영역에는 추가 상세 요청이 없는지 확인한다.
- 격리 PostgreSQL에서 셀 밀도 전체 집계, 5,000개를 넘는 상세 페이지의 누락 여부, PD-L1 보관본 역할 제한, IHC 수정본 클래스·임계값·원본 복원 4개 백엔드 테스트가 통과했다.
- `scripts/verify-integration.sh --demo ihc`가 통과했다. Chromium에서 6,200개 세포의 두 번째 페이지를 지연시켜 밀도 표시가 유지되는지 확인하고, 페이지가 모두 온 뒤 개별 셀 전환과 20×→40×→전체 화면 시 캐시 재사용을 확인했다.
- HTTPS 9920에서 실제 등록 PD-L1 보관본의 41,373개 세포가 전체 분포 합계에 포함됐다. 20×에서 상세 요청 2회가 발생했고, 같은 중심의 40×에서는 추가 상세 요청이 없었다. IHC 페이지 완결성과 수정·복원은 위 격리 픽스처로 확인했다.
