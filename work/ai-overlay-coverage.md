# AI 세포 오버레이의 전체 표시와 줌 재사용

## 기준과 표시 방식

SaaS 베이스 `d3741bc`의 `frontend/js/tile-viewer.js`에 있는 `_renderDenseCellsRaster`와 `_renderCells`를 기준으로 한다. 넓은 시야에서는 세포의 실제 픽셀 좌표에 작은 래스터 점을 그리고, 5 µm/px 이하의 가까운 시야에서는 클래스별 테두리를 그린다. 가까운 시야에서도 세포가 50,000개를 넘으면 래스터를 사용한다. 같은 화면 픽셀에 여러 세포가 겹칠 수 있다.

기존 5,000개 응답 제한부터 벗어나기 위해 한때 클래스별 밀도 격자를 사용했다. 현재 Viewer의 PD-L1과 IHC(Ki-67, ER, PR, HER2)는 선택 결과의 전체 세포 레코드를 압축해 한 번 읽는다. 위치, 클래스, IHC 수정본·세포 ID·신뢰도를 보존한다. 메모리의 위치 인덱스로 현재 영역의 그리기와 가장 가까운 세포 선택을 처리한다. 같은 결과 버전에서 확대·이동·Fit 조작은 요청을 다시 보내지 않는다. 추가 결과 버전을 열거나 명시적으로 다시 요청할 때 해당 버전을 불러온다.

기존 결과 점수·권한·임계값 계약과 DB 스키마를 사용한다. 영역별 API는 기존 소비자용으로 남아 있다.

## 재현과 검증

- 결과가 연결된 스캔을 **Open Viewer**로 열면 넓은 시야에서 실제 좌표의 세포 점을 확인할 수 있다. 20×와 40×로 확대하거나 **Fit to Window**로 복귀한다. 브라우저 Network에서 동일 결과의 `/overlay` 요청을 확인한다.
- 격리 PostgreSQL에서 6,131개 점의 바이너리 좌표·클래스 보존, 상세 페이지의 완결성, PD-L1 역할 구분, IHC 수정본 클래스·임계값·원본 복원 4개 백엔드 테스트를 실행했다.
- `scripts/verify-integration.sh --demo ihc` 통과. 6,200개 세포 픽스처에서 떨어진 두 세포 좌표에 점이 보이고 그 사이 픽셀이 투명한 것을 확인했다. Ki-67·ER·PR, HER2, PD-L1와 Multi View 회귀 검증을 함께 실행했다.
- 9920 Chrome 테스트에서 보관 PD-L1 결과의 41,373개 세포를 확인했다. Fit에서 점, 20×에서 테두리를 확인했고 40×를 거쳐 Fit으로 돌아갈 때까지 동일 결과의 오버레이 요청은 1회였다.
